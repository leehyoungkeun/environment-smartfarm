# KS X 3267 / KOAT 116 자가 리허설 체크리스트

버전 1.0 (2026-09-02). 116 검정 「마. 시험방법」 각 절차를 **실물 HW 없이 시뮬레이터 + 실제 UI**로 미리 통과시켜 화면 공백을 잡는다.
각 항목: **[화면] → [조작] → [통과 기준] → [시뮬 재현]**. `☐` 는 리허설 시 체크.

---

## 0. 사전 준비 (한 번)
- ☐ **시뮬레이터 기동** (RPi 1호): `pm2 start ks3267-sim`(TCP 5020, 구동기 unit 1 / 센서 unit 2) + `pm2 start ks3267d`(`--tcp 127.0.0.1:5020 --units 1,2`). `pm2 ls` 로 online 확인.
- ☐ **표준 노드 매핑 존재**: 설정 › 표준노드(`KsNodeManager`)에서 드라이버 "연결됨" + 노드 카드. 하우스에 `ks_test_sw1`(스위치)·센서 매핑(온도 idx1 등) 1개 이상.
- ☐ **30일 데이터 확보**: 서버 `actuator_status` 30일치(임의값 가능). 부족하면 시뮬 구동기를 30일 백필하거나 입고 전까지 축적. 조회로 1/7/30일 데이터 존재 확인.
- ☐ **관제 방식 목록 확정**: 본체 키오스크 / 웹(smartgreen.kr) / 모바일 Android / iOS — 신고할 방식마다 §1·§2 (가) 연결해제 시험을 **반복**해야 함(방식 수 = 배수).

## 1. 센서 데이터 연계 성능시험

### 1-가. 실시간 센서 상태 연계 + 연결해제·재연결 5회
- **화면**: 대시보드 + 설정 › 표준노드
- **조작**: 센서 노드 전부 매핑 → 값이 대시보드에 실시간 출력 확인 → **1/3 이상 센서** 연결단자 해제(시뮬: 해당 unit 정지) → 재연결 → **2분 이내** 값 복귀 확인 → **5회 반복** → **각 관제 방식(웹·키오스크·모바일)마다 반복**
- **통과 기준**: 재연결 후 2분 이내 정상 값 출력, 5회 모두, 모든 관제 방식.
- **시뮬 재현**: `pm2 stop ks3267d`(또는 시뮬 unit) → 3분+ 뒤 값 "비어 있음"(지어내지 않음) → `pm2 start` → 2분 내 복귀. (C3 실증에서 STALE 억제 확인됨)

### 1-나. 데이터 전송 손실률 (24h, 3% 이내)
- **화면**: 보고서 › 데이터 조회·추출(`DataExplorer`)
- **조작**: 24시간 유지 후 1분 단위 조회 → 기대 행수(1440) 대비 실제 저장 행수로 손실률 산출
- **통과 기준**: 손실률 3% 이내. 결측은 빈 칸(0 아님).
- **시뮬 재현**: 24h 연속 가동 후 `SELECT count(*) FROM sensor 조회`; 손실률 = (1 − 정상행/1440)×100.

### 1-다. 데이터 시각화 (3분 이내, 1/7/30일)
- **화면**: 대시보드 `SensorChart`
- **조작**: 센서 1개 → 1시간/1일/7일/30일 각 전환(30일=1시간 단위) → 1개 추가 → 3개↑면 항목 바꿔 **3회 반복**
- **통과 기준**: 각 조회기간 그래프가 **3분 이내** 정상 출력, 일부/전체 항목.

### 1-라. 데이터 조회·추출 (csv/txt/xls, 3분 이내)
- **화면**: 보고서 › 데이터 조회·추출
- **조작**: 센서 1개 조회기간별 3분내 출력 → 임의 개수 추가 조회 → **.csv/.txt 서버 추출 + .xlsx 클라이언트 추출**
- **통과 기준**: 3분 이내 표 출력 + 3개 형식 추출 파일 정상(결측 빈 칸).

### 1-마. 데이터 유지 (전원차단 30분 후 복구)
- **화면**: 전 화면
- **조작**: 통합제어기(RPi) 전원 차단 **30분↑** → 인가 → 센서 재연계 + 저장 데이터 조회·시각화·추출 정상 확인
- **통과 기준**: 재기동 후 자동 복귀, 기존 데이터 조회·추출 가능.
- **시뮬 재현**: RPi 재부팅(`sudo reboot`) → pm2 resurrect 로 앱·드라이버 복귀 → 데이터 유지 확인.

## 2. 구동기 데이터 연계 및 제어 성능시험

### 2-가. 실시간 구동기 상태 연계 + 연결해제·재연결 5회
- **화면**: 제어판(`ControlPanel`) 📐 배지
- **조작**: 구동기 노드 전부 매핑 → 상태 출력 확인 → 1/3 이상 해제·재연결 → 2분내 상태 복귀 → 5회 → 각 관제 방식 반복
- **통과 기준**: 1-가와 동일 기준(구동기 상태).

### 2-나. 구동기 동작 제어
- **화면**: 제어판
- **조작**: 구동기 1개 선택 → **열기/정지/닫기**(개폐기) 또는 **ON/OFF**(스위치) 명령 실행 → 시뮬 노드가 명령 수신 + 상태(📐 배지: `켜짐 Ns`·`열리는 중`·`READY`) 정상 출력 → **모든 구동기 순차 + 각 관제 방식 반복**
- **통과 기준**: 명령대로 작동 + 상태·남은시간 정상 표시, 거부 시 실패 이력.
- **시뮬 재현**: 제어판에서 ks_test_sw1 ON/시간제한 ON → 시뮬 로그(`--log-frames`)에 cmd 202/0 수신·remain 감소 확인 (자가시험 selftest_sps7466.py 와 동일 입구).

### 2-다·라·마. 전송 손실률 / 시각화 / 조회·추출 / 유지
- **화면**: 보고서 › 데이터 조회·추출(**표준 구동기 상태**), SensorChart
- **조작·기준**: 1-나~마와 동일(대상만 구동기 상태). 표준 구동기 1분 스냅샷(`actuator_status`) 기준.
- **시뮬 재현**: C3 실증 그대로 — 60초 스냅샷 누적, `pm2 stop ks3267d` 시 3분+ 결측(손실 명시), 재기동 재개.

## 3. 조작의 난이도 시험 (제품 매뉴얼대로 시험자 직접 조작)
사용설명서 §3~6 절차를 시험자가 그대로 따라할 수 있는지. 각 항목 매뉴얼 페이지 대조:
- ☐ (1) **센서·센서노드 연계** — 설정 › 표준노드 탐색 + 센서 "표준 노드에 매핑" (§4.2)
- ☐ (2) **구동기·구동기노드 연계** — 장치 프로토콜 "표준 노드" + unit/kind/n (§4.1)
- ☐ (3) 양액공급기 연계 — (양액 미개발, 스코프 확인 필요 → 시험기관 문의)
- ☐ (4) **구동기 자동제어 설정** — 설정 › 자동화규칙(`AutomationManager`)에서 표준 장치 규칙 생성 (§5 자동화)
- ☐ (5) **데이터 조회·시각화·추출** — 보고서 · 대시보드 차트 (§6)
- **통과 기준**: 매뉴얼만 보고 각 조작 완료 가능(용이).

## 4. 프로토콜 적합성 (SPS X KOAT-0004-7466 §5.4 제어기 공통 + §5.5 구동기능 포함 제어기)
- **도구**: `tools/ks3267-sim/selftest_sps7466.py` (시뮬 `--units 1:actuator,2:sensor --ctl 5030` = 시험장비 역할)
- **조작**: `python selftest_sps7466.py` → 화면과 같은 입구(NR `POST /api/control/local`, modbus 프로필 동봉)로 제어 → 시뮬이 cmd/opid/time 수신·remain 감소·READY 복귀 검증
- **통과 기준**: **표4 시나리오 전부 통과** (현재 7/7). 증적 `docs/ksx3267/self-test/evidence-*/`.
- 참고: 비정상(예외·타임아웃)은 구동기 노드(§5.3) 전용 — 제어기 시험(5.4/5.5)엔 없음.
