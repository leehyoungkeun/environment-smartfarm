## 1. 센서 데이터 연계 성능시험

### 1-가. 실시간 센서 상태 연계 + 연결해제·재연결 5회
- **화면**: 대시보드 + 설정 › 표준노드
- **조작**: 센서 노드 전부 매핑 → 값이 대시보드에 실시간 출력 확인 → **1/3 이상 센서** 연결단자 해제(시뮬: 해당 unit 정지) → 재연결 → **2분 이내** 값 복귀 확인 → **5회 반복** → **각 관제 방식(웹·키오스크·모바일)마다 반복**
- **통과 기준**: 재연결 후 2분 이내 정상 값 출력, 5회 모두, 모든 관제 방식.
- **자동 시험**: `selftest_sps7466.py --only 116-재연결` — 시험장비 `/fault timeout` 으로 버스 전 노드를 해제했다가 재연결하기를 5회, 드라이버와 화면 경로(NR 프록시)의 복귀 시간을 잰다. **2026-09-14 17/17 통과, 5회 모두 3.0초 복귀** (`evidence-20260914-102045/`). 데이터 공백은 3분 넘게 끊겨야 생긴다(STALE 억제, C3 실증).

### 1-나. 데이터 전송 손실률 (24h, 3% 이내)
- **화면**: 보고서 › 데이터 조회·추출(`DataExplorer`)
- **조작**: 24시간 유지 후 1분 단위 조회 → 기대 행수(1440) 대비 실제 저장 행수로 손실률 산출

- **시뮬 재현**: 24h 연속 가동 후 `SELECT count(*) FROM sensor 조회`; 손실률 = (1 − 정상행/1440)×100.

### 1-다. 데이터 시각화 (3분 이내, 1/7/30일)
- **화면**: 대시보드 `SensorChart`
- **조작**: 센서 1개 → 1시간/1일/7일/30일 각 전환(30일=1시간 단위) → 1개 추가 → 3개↑면 항목 바꿔 **3회 반복**
- **통과 기준**: 각 조회기간 그래프가 **3분 이내** 정상 출력, 일부/전체 항목.

### 1-라. 데이터 조회·추출 (csv/txt/xls, 3분 이내)
- **화면**: 보고서 › 데이터 조회·추출
- **조작**: 센서 1개 조회기간별 3분내 출력 → 임의 개수 추가 조회 → **.csv/.txt 서버 추출 + .xlsx 클라이언트 추출**
- **통과 기준**: 3분 이내 표 출력 + 3개 형식 추출 파일 정상(결측 빈 칸).

### 1-마. 데이터 유지 (전원차단 30분 후 복구)
- **화면**: 전 화면
- **조작**: 통합제어기(RPi) 전원 차단 **30분↑** → 인가 → 센서 재연계 + 저장 데이터 조회·시각화·추출 정상 확인

- **시뮬 재현**: RPi 재부팅(`sudo reboot`) → pm2 resurrect 로 앱·드라이버 복귀 → 데이터 유지 확인. 실제 30분 차단 드릴은 그날 손실 2.08%(30행)라 **30일 창을 끊지 않는다.** 단 복구까지 합계 43분을 넘기면 끊긴다.
