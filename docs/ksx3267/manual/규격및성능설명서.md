**기종명**: 통합제어기
**작성**: 2026-09-28 (양식 2025.02.03 개정판 기준)

> 표기 규칙
> - **(1호 실측)** = 기준 기체(RPi 1호)에서 명령으로 확인한 값. 시험 기체 제작 후 같은지 확인만 하면 된다.
> - `〔 〕` = **케이그린텍이 기입**. 실물·조달·회사 정보라 소프트웨어에서 알 수 없다.

## 5. 기체의 관제 방식

### 가. 관제(모니터링 및 제어) 지원 여부
| 본체(컨트롤박스) 모니터 | 본체 패널 | 본체 기타 | 웹(Web) | 모바일 Android | 모바일 iOS |
|---|---|---|---|---|---|
| 〔○/공란〕 | **○** | 공란 | **○** | **○** | **○** |

- 본체 패널: 7인치 터치패널 키오스크(제어기 자체 화면, 인터넷 없이 동작)
- 웹: `smartgreen.kr` (PC·태블릿 브라우저)
- 모바일: PWA — Android·iOS 모두 홈 화면 설치로 앱처럼 사용

> ⚠ **관제 방식 개수 = 연결 해제·재연결 시험 반복 횟수**(문의 3번). 4개를 신고하면 4회 반복일 수 있다.
> Android·iOS는 같은 PWA라 하나로 신고 가능한지 기관 확인이 필요하다. 답에 따라 이 표를 줄인다.

### 나. 통합제어기 관제 방식
**☑ 복합형** — 노드(센서&구동기) ↔ 로컬서버 ↔ 클라우드

| 구간 | 통신방식 |
|---|---|
| 노드 ↔ 로컬서버(제어기 본체) | **RS-485 Modbus RTU** (9600 8N1, KS X 3267 디폴트맵) |
| 로컬서버 ↔ 클라우드 | **인터넷** — HTTPS(REST) + MQTT over TLS |

- 제어기 본체가 로컬서버를 겸한다. 인터넷이 끊겨도 본체 패널에서 조회·제어가 이어진다(로컬 SQLite·로컬 REST).

## 붙임 1. 성능 (KOAT 116 성능시험 기준 대응)

| 116 성능 기준 | 본 제어기 구현 | 근거 |
|---|---|---|
| 센서 상태정보 데이터 **손실률 3 % 이내** | 1분 주기 수집, 결측은 빈 칸(미조작·미보고 구분), 로컬 SQLite 버퍼 + 재전송 | actuator/센서 파이프라인 |
| 구동기 상태정보 **손실률 3 % 이내** | 표준 구동기 1분 스냅샷(변화 없어도 하트비트 기록), 3분 무응답 시 손실로 명시(값 미조작) | `actuator_status` 1분 버킷 |
| 2항목 이상 **시각화 1시간 이하 단위 + 1·7·30일** | 대시보드 차트: 1시간·6시간·24시간·7일·30일(30일=1시간 단위) | SensorChart |
| **조회 1분 단위 + 1·7·30일** (일부/전체 항목) | 보고서 › 데이터 조회·추출: 센서/제어이력/표준구동기, 1분 행 표, 기간·항목 선택 | DataExplorer |
| **추출 .csv/.txt/.xls** (1분 단위, 1·7·30일) | 서버 CSV/TXT(원본), 클라이언트 XLSX. 결측 빈 칸 | `/api/.../export` |
| 종료/**전원 차단·인가 후 데이터 복구** | 재기동 시 드라이버·화면 자동 복귀, 데이터는 로컬 SQLite·클라우드에 유지 → 조회·추출 가능 | pm2 resurrect + 영구 저장 |
| **연결단자 해제·재연결 후 2분 이내** 정상 (5회) | 드라이버 2초 폴링, 응답 없음 즉시 표시, 재연결 다음 폴링에 복귀. 자동 시험 5회 모두 **3.0초** 복귀 | 자가시험 `116-재연결` 17/17 |
| 제어(구동기 명령·상태 readback) | 표준 노드 OPID 명령·상태 폴링(2초)·1분 스냅샷, 상태코드·남은시간 표시 | ks3267 드라이버 |

**프로토콜 적합성 (SPS X KOAT-0004-7466 §5.4/5.5)**: 디폴트맵·레벨1·프로토콜버전 10 기준 자가시험 표4 시나리오 7/7, §5.5.2 완전판 13/13, §5.5.3 완전판 14/14, 116 연결단자 해제·재연결 5회 17/17 통과(증적 `docs/ksx3267/self-test/`, 통합본 `self-test/성적서.md`). 본시험은 시험기관 시험장비(노드) 지참으로 진행.

**소프트웨어 구성**: Node-RED(오케스트레이터) + ks3267 드라이버 데몬(pymodbus, 표준 노드 전용 포트) + 백엔드(Express, PostgreSQL/TimescaleDB) + 프론트(React PWA·현장 키오스크). 자체 장치와 표준 노드는 이중 드라이버로 공존.
